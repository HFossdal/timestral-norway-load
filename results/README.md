# Results: what is where

Everything here is produced by `python -m src.report`, `python -m src.headline` and `python -m src.synthetic --report` from the cached forecasts in `results/cache/` (not in the repo). Each table is saved twice: `.csv` (full precision) and `.md` (rounded, readable).

Technical-review updates are generated by `python -m src.review` (1-, 3- and 7-day bootstrap sensitivity), `python -m src.review --refresh-existing` (affected original one-day paired tables) and `python -m src.review_docs` (README tables and the corrected synthetic section from generated outputs). `run_review.sh` records the complete sequence.

**Synthetic cache version.** Corrected experiments use only `results/cache/synthetic/matched-v2/`, with five matched seeds (0–4). The unversioned synthetic caches predate the matching fix and are never read by the corrected report. It requires the complete 11,250-row grid and rejects duplicates or mixed versions. Noise and drift are generated on a shared calendar before slicing contexts. Synthetic bootstrap intervals resample seeds and origins, retaining all zones together; `synthetic_seed_summary` reports each seed separately and `synthetic_length_change` includes the SD and range of the seed-specific paired changes. `synthetic_manifest.json` records inputs and package versions.

**Real-data sensitivity.** `review_bootstrap` contains every 1/3/7-day result for context gains and Timestral comparisons with Chronos-2/TimesFM, including pooled results stratified within winters. `review_bootstrap_headline` selects the test-winter all-hour rows, without selecting a block length. `review_bootstrap_manifest.json` records the resampling specification and missing-cache audit. Pairing includes forecast origin to distinguish overlapping target hours at spring DST. These sensitivity checks reuse model outputs; no real-data inference is repeated. Original tables retain one-day intervals unless explicitly labelled otherwise.

`review_calibration_bootstrap` adds 567 one-sided miss-rate checks at 1/3/7 days for observed and actual forecast weather, before and after temperature-bin CQR, with test-winter and leave-one-winter-out fits. It conditions on the fitted corrections, without refitting them in each bootstrap draw. Generate it separately with `python -m src.review --calibration-bootstrap`, or as part of the default review analysis.

**Reserve tables.** Margins and their one-day intervals are retrospective test-period estimates of summed zone-wise peak-error quantiles, not margins fitted before and validated on the test winter, nor joint five-zone coverage guarantees.

**Calibration information.** Supplementary Mondrian CQR and bias-plus-CQR groups use observed temperature only in the observed-weather experiments. Forecast/noisy-weather experiments use their supplied weather values to choose groups; observed cold/peak flags are used only to score outcomes. The main asymmetric temperature-bin correction already followed this rule. `python -m src.review --calibration-only` refreshes the affected supplementary tables from cached predictions.

**Synthetic audit data.** `tables/synthetic_responses_matched_v2.csv.gz` contains all corrected per-model/zone/origin/seed responses. `response_mw_per_degree_colder` is positive when demand increases for colder future temperatures. This small archive permits independent checks of pairing, seed variability and bootstrap summaries without rerunning inference; its hash is recorded in `synthetic_manifest.json`. It is an output archive, not an inference cache.

Synthetic analytical references are recomputed per origin, including the 0.9 holiday multiplier on target hours. This corrects reference metadata in earlier matched-v2 checkpoints without altering their model inputs or predictions. Normalised summaries average the per-forecast response/reference ratios; the reference itself can vary across origins.

`review_probe_bootstrap` adds 1/3/7-day checks for the real-data temperature probe in both winters. It includes paired differences between models' context-length effects; separate model intervals alone are not used to test their difference. `probe_bootstrap_sensitivity.png` displays all three block lengths for the three headline models.

**Naming.** `<table>_<origin>_ctx<hours>`:
- `noon_before_ctx2688`: main setting (forecast at 12:00 the day before, 16 weeks of history)
- `noon_before_ctx672`: 4 weeks of history (the diagnosis setting)
- `midnight_ctx672`: midnight origin, 4 weeks (secondary comparison)

Tables without a suffix apply to all settings (thresholds, station lists).

**Glossary of column names.** `cov80` / `cov90`: share of hours inside the 80% / 90% band. `above80` / `below80`: share above q0.90 / below q0.10 (target 0.10 each). `width80`: mean band width (MW). `bias`: actual minus median (positive = under-forecast). `dMAE`, `dPinball`: paired difference b - a (negative = b better), with `_lo` / `_hi` 95% day-level bootstrap bounds. `_temp_fc`: real MET Nordic weather forecast; `_temp_noisy`: synthetic ±1.5 °C error; `_temp_multi`: several stations per zone; `_temp_cold`: probe run (future 3 °C colder).
